# ASM Examples v1.0

## Purpose

This document provides examples of the Formal Core of the
Accounting State Model (ASM).

The purpose of these examples is to demonstrate the relationship between:

$$
Event
\rightarrow
Effect
\rightarrow
State
$$

without introducing domain-specific concepts.

Accounting-specific examples are introduced only as a preview of higher
layers.

---

## Generic Event Example

Consider a system that tracks the number of objects.

The State Space is:

$$
\mathcal{S}=\mathbb{Z}
$$

where each State represents the current quantity.

A State is:

$$
S_t\in\mathcal{S}
$$

Assume the initial State:

$$
S_0=10
$$

An Event occurs:

$$
e_1\in\mathcal{E}
$$

where the Event represents:

"One object is added."

The Effect generated by the Event is:

$$
\alpha(e_1)=+1
$$

Therefore:

$$
\alpha(e_1)\in\Delta\mathcal{S}
$$

The State transition is:

$$
S_1
=
\delta(S_0,\alpha(e_1))
$$

Assuming addition as the transition rule:

$$
S_1=10+1
$$

therefore:

$$
S_1=11
$$

The Event itself is not the State change.

The relationship is:

$$
e_1
\rightarrow
\alpha(e_1)
\rightarrow
S_1
$$

## Simple State Transition Example

Consider a task management system.

The State Space contains possible task states:

$$
\mathcal{S}
=
\{
Todo,
Doing,
Done
\}
$$

The initial State is:

$$
S_0=Todo
$$

An Event occurs:

$$
e_1\in\mathcal{E}
$$

representing:

"Task started."

The Effect is:

$$
\alpha(e_1)
=
Todo\rightarrow Doing
$$

The Transition Function applies the Effect:

$$
S_1
=
\delta(S_0,\alpha(e_1))
$$

Therefore:

$$
S_1=Doing
$$

In ASM:

- Event represents what happened.
- Effect represents the state change.
- Transition represents how the change is applied.

## History Reconstruction Example

Consider a system with the following History:

$$
H_t
=
((e_1,t_1),(e_2,t_2))
$$

where:

$$
t_1<t_2
$$

The initial State is:

$$
S_0
$$

The first Event produces:

$$
\alpha(e_1)
$$

and:

$$
S_1
=
\delta(S_0,\alpha(e_1))
$$

The second Event produces:

$$
\alpha(e_2)
$$

and:

$$
S_2
=
\delta(S_1,\alpha(e_2))
$$

Therefore:

$$
S_2
=
G(H_t)
$$

The current State is derived from accumulated History.

The State does not replace the History.

## Multiple Representation Example

A single History may have different representations depending on the
required Task.

Let:

$$
H_t\in\mathcal{H}
$$

Two Tasks exist:

$$
Q_1,Q_2\in\mathcal{Q}
$$

For example:

- $Q_1$: Show operational status.
- $Q_2$: Analyze historical changes.

The representations are:

$$
F_{Q_1}:
\mathcal{H}
\rightarrow
\mathcal{Y}_{Q_1}
$$

and:

$$
F_{Q_2}:
\mathcal{H}
\rightarrow
\mathcal{Y}_{Q_2}
$$

The results may differ:

$$
F_{Q_1}(H_t)
\neq
F_{Q_2}(H_t)
$$

even though the source History is identical.

Therefore:

$$
History
\neq
Representation
$$

## Constraint Preservation Example

Consider a State Space where a constraint must always hold.

Let:

$$
\kappa:
\mathcal{S}
\rightarrow
\mathbb{R}
$$

define a validity condition.

A valid State satisfies:

$$
\kappa(S_t)=0
$$

Assume:

$$
\kappa(S_0)=0
$$

An Event occurs:

$$
e\in\mathcal{E}
$$

The transition is:

$$
S_{t+1}
=
\delta(S_t,\alpha(e))
$$

A valid transition must preserve:

$$
\kappa(S_{t+1})=0
$$

Therefore:

$$
\text{Valid State}
\rightarrow
\text{Valid State}
$$

## Accounting Domain Preview

The Formal Core does not define accounting concepts directly.

Instead, an accounting domain introduces a specialized State Space:

$$
\mathcal{S}_{acc}
$$

The relationship between Accounting State and ASM State is defined by an
mapping function:

$$
\iota_{acc}:
\mathcal{S}_{acc}
\rightarrow
\mathcal{S}
$$

This means that an Accounting State can be represented as an ASM State.

An Accounting Event is defined as:

$$
e_{acc}\in\mathcal{E}_{acc}
$$

and generates an Accounting Effect:

$$
\alpha_{acc}(e_{acc})
\in
\Delta\mathcal{S}_{acc}
$$

The Accounting State transition is:

$$
S_{acc,t+1}
=
\delta_{acc}
(
S_{acc,t},
\alpha_{acc}(e_{acc})
)
$$

At this layer, domain-specific concepts are introduced, including:

- Assets
- Liabilities
- Equity
- Double Entry

The Formal Core provides the transition structure.

The Accounting Layer provides the domain meaning.

## Summary

ASM describes systems through:

$$
Reality
\rightarrow
Evidence
\rightarrow
Event
\rightarrow
Effect
\rightarrow
State
\rightarrow
Representation
$$

The essential state transition is:

$$
S_{t+1}
=
\delta(S_t,\alpha(e))
$$

Events explain why change occurs.

Effects explain what changes.

States explain the resulting condition.

Representations explain how the condition is viewed.
