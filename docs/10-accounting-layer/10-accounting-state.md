# ASM Accounting State v1.2

## Purpose

This document defines the concept of Accounting State in the Accounting
Layer of the Accounting State Model (ASM).

The purpose is to define what an Accounting State represents before
introducing specific accounting structures such as Assets, Liabilities,
Equity, and Double Entry.

The Accounting State is a specialization of the State concept defined in
the Formal Core.

---

## Relationship with Formal Core

The Formal Core defines a general State:

$$
S_t\in\mathcal{S}
$$

where $S_t$ represents the condition of a modeled system at time $t$.

The Accounting Layer specializes this concept:

$$
S_{acc,t}\in\mathcal{S}_{acc}
$$

where:

- $S_{acc,t}$ represents an Accounting State.
- $\mathcal{S}_{acc}$ represents the Accounting State Space.

The relationship is:

$$
\mathcal{S}_{acc}
\subseteq
\mathcal{S}
$$

The Accounting State is a domain-specific State.

---

## Accounting State Concept

An Accounting State represents the current accounting condition of an
economic entity.

It is not a record of transactions.

It is the condition obtained after applying Accounting Effects generated
from accumulated Accounting Events.

The fundamental relationship is:

$$
Accounting\ History
\rightarrow
Accounting\ State
$$

The Accounting State answers:

"What is the current accounting condition?"

The Accounting History answers:

"What Accounting Events produced this condition?"

Therefore:

$$
Accounting\ State
\neq
Accounting\ History
$$

---

## Formal Definition

The Accounting State Space is:

$$
\mathcal{S}_{acc}
$$

An Accounting State is an element of this space:

$$
S_{acc,t}
\in
\mathcal{S}_{acc}
$$

The Accounting State changes through Accounting Effects.

The transition is:

$$
S_{acc,t+1}
=
\delta_{acc}
(
S_{acc,t},
\alpha_{acc}(e_{acc})
)
$$

where:

- $e_{acc}$ is an Accounting Event.
- $\alpha_{acc}(e_{acc})$ is the Accounting Effect generated by the Event.
- $\delta_{acc}$ is the Accounting State Transition Function.

---

## State Generation from History

Accounting Events are accumulated as Accounting History.

$$
H_{acc}(t)
\in
(\mathcal{E}_{acc}\times T)^*
$$

The Accounting State can be reconstructed from accumulated History:

$$
S_{acc,t}
=
G_{acc}(H_{acc}(t))
$$

where:

$$
G_{acc}:
\mathcal{H}_{acc}
\rightarrow
\mathcal{S}_{acc}
$$

represents the State Generation Function.

The relationship is:

$$
Accounting\ Event
\rightarrow
Accounting\ History
\rightarrow
Accounting\ State
$$

---

## State Transition Perspective

Traditional accounting often starts from records.

ASM starts from state transition.

The fundamental transition structure is:

$$
Accounting\ Event
\rightarrow
Accounting\ Effect
\rightarrow
Accounting\ State
$$

The Accounting Event describes:

"What occurred?"

The Accounting Effect describes:

"What changed?"

The Accounting State describes:

"What is the resulting condition?"

The Transition Function describes:

"How is the change applied?"

Therefore:

$$
Effect
\neq
State
$$

and:

$$
Effect
\neq
Transition
$$

---

## Relationship Between History and Transition

Accounting History preserves the ordered sequence of Accounting Events.

The State Transition mechanism applies the corresponding Accounting
Effects.

For:

$$
H_{acc}(t)
=
((e_1,t_1),(e_2,t_2),\dots,(e_n,t_n))
$$

the resulting State is obtained through sequential transitions:

$$
S_{i+1}
=
\delta_{acc}
(
S_i,
\alpha_{acc}(e_i)
)
$$

Therefore:

$$
S_{acc,t}
=
G_{acc}(H_{acc}(t))
$$

History provides the Events.

Effects provide the changes.

Transitions produce the resulting State.

---

## State and History Separation

An Accounting State does not necessarily contain the complete Accounting
History.

Formally, there may exist:

$$
H_1,H_2\in\mathcal{H}_{acc}
$$

such that:

$$
H_1\neq H_2
$$

but:

$$
G_{acc}(H_1)
=
G_{acc}(H_2)
$$

This means different histories may produce the same Accounting State.

Therefore:

$$
State
\neq
History
$$

---

## Accounting State as a Sufficient Representation

An Accounting State is sufficient when it preserves the information
required for future Accounting State transitions.

For an Accounting Event:

$$
e_{acc}\in\mathcal{E}_{acc}
$$

the next State is determined by:

$$
S_{acc,t+1}
=
\delta_{acc}
(
S_{acc,t},
\alpha_{acc}(e_{acc})
)
$$

The State does not need to contain all historical information.

It only needs to preserve information required by the transition model.

---

## Future Extension

The Accounting State Space will later be specialized through Accounting
Structure.

Future concepts include:

- Accounting dimensions
- Accounting constraints
- Balance relationships
- Double Entry representation

These concepts define the internal structure of:

$$
\mathcal{S}_{acc}
$$

They are introduced in higher layers.

---

## Summary

The Accounting State is a domain-specific State in ASM.

The fundamental structures are:

$$
Accounting\ Event
\rightarrow
Accounting\ History
\rightarrow
Accounting\ State
$$

and:

$$
Accounting\ Event
\rightarrow
Accounting\ Effect
\rightarrow
Accounting\ State
$$

The Accounting State is:

- a condition, not a record
- derived from Accounting History
- updated through Accounting Effects
- constrained by Accounting Structure

ASM models accounting as:

$$
\boxed{
A\ state\ transition\ system\ over\ accounting\ events
}
$$
