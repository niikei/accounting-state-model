# ASM Formal Core Overview v1.1

## Purpose

This document provides an overview of the Formal Core of the
Accounting State Model (ASM).

The Formal Core defines the general mathematical structure used to model
systems as event-driven state transitions.

Domain-specific concepts, including accounting concepts, are introduced
in higher layers.

---

## What is ASM?

The Accounting State Model (ASM) is a mathematical framework for
representing systems through:

$$
Event
\rightarrow
Effect
\rightarrow
State
$$

An Event represents a cause of change.

An Effect represents the change produced by the Event.

A State represents the resulting condition of the system.

---

## Fundamental Model

The fundamental transition structure of ASM is:

$$
S_{t+1}
=
\delta(S_t,\alpha(e))
$$

where:

- $S_t$ represents the current State.
- $e$ represents an Event.
- $\alpha(e)$ represents the Effect generated by the Event.
- $\delta$ represents the State Transition Function.

ASM separates:

| Concept | Meaning |
| --- | --- |
| Event | What happened |
| Effect | What changed |
| State | Resulting condition |
| Transition | How the change is applied |

---

## From Reality to Representation

ASM does not directly model Reality.

Instead, it represents a process from observation to representation:

$$
Reality
\rightarrow
Evidence
\rightarrow
Event
\rightarrow
History
\rightarrow
State
\rightarrow
Representation
$$

The complete structure is:

$$
\mathcal{R}
\rightarrow
\mathcal{Z}
\rightarrow
\mathcal{E}
\rightarrow
\mathcal{H}
\rightarrow
\mathcal{S}
\rightarrow
\mathcal{Y}_Q
$$

where:

- $\mathcal{R}$ represents Reality.
- $\mathcal{Z}$ represents Evidence.
- $\mathcal{E}$ represents Event Space.
- $\mathcal{H}$ represents History.
- $\mathcal{S}$ represents State Space.
- $\mathcal{Y}_Q$ represents purpose-dependent Representation Space.

---

## Event, Effect, and History

ASM distinguishes between the transition mechanism and the information
preservation mechanism.

The transition mechanism is:

$$
Event
\rightarrow
Effect
\rightarrow
State
$$

The information preservation mechanism is:

$$
Event
\rightarrow
History
\rightarrow
State
$$

An Event produces an Effect for state transition.

The same Event is preserved as History for reconstruction.

---

## Core Concepts

The Formal Core defines the following concepts.

---

## Reality

Reality represents objects and changes that exist independently of the
model.

$$
\mathcal{R}
$$

---

## Evidence

Evidence represents observable information obtained from Reality.

$$
\mathcal{Z}
$$

Evidence is the basis from which Events are recognized.

---

## Event

An Event represents an occurrence recognized by ASM.

$$
e\in\mathcal{E}
$$

An Event is the causal input of a state transition.

---

## Effect

An Effect represents the change generated by an Event.

$$
\alpha(e)\in\Delta\mathcal{S}
$$

An Effect represents an instantaneous state change.

Accumulated Effects over time may form Flow.

Therefore:

$$
Effect
\neq
Flow
$$

---

## State

A State represents the condition of the modeled system.

$$
S_t\in\mathcal{S}
$$

The State is updated through the Transition Function:

$$
S_{t+1}
=
\delta(S_t,\alpha(e))
$$

---

## History

ASM preserves Events as History.

$$
H(t)\in(\mathcal{E}\times T)^*
$$

History represents the ordered accumulation of Events.

A State can be reconstructed from accumulated History:

$$
S_t=G(H(t))
$$

Therefore:

$$
History
\neq
State
$$

History stores Events.

State stores the resulting condition derived from Events.

---

## Representation

A Representation transforms underlying ASM information into information
suitable for a specific purpose.

The general Representation Function is:

$$
F_Q:
(\mathcal{H},\mathcal{S})
\rightarrow
\mathcal{Y}_Q
$$

where:

- $\mathcal{H}$ represents History.
- $\mathcal{S}$ represents State.
- $Q$ represents a purpose or Task.
- $\mathcal{Y}_Q$ represents the resulting Representation Space.

---

## Purpose-Dependent Views

A single History and State may generate multiple Representations.

For:

$$
Q\in\mathcal{Q}
$$

there exists:

$$
F_Q:
(\mathcal{H},\mathcal{S})
\rightarrow
\mathcal{Y}_Q
$$

Therefore:

$$
F_{Q_1}(H,S)
\neq
F_{Q_2}(H,S)
$$

may hold.

ASM separates:

- underlying information
- current State
- purpose-dependent Representation

---

## Formal Core Structure

The Formal Core consists of:

| Document | Purpose |
| --- | --- |
| Notation | Defines mathematical symbols |
| Axioms | Defines fundamental assumptions |
| Definitions | Defines mathematical objects |
| Theorems | Derives mathematical properties |
| Corollaries | Applies derived properties |

---

## Layer Extension

The Formal Core does not define specific domains.

Instead, domains specialize ASM by introducing constrained subspaces.

For example, accounting introduces:

$$
\mathcal{S}_{acc}
$$

as a specialized State Space.

The relationship is:

$$
\mathcal{S}_{acc}
\subseteq
\mathcal{S}
$$

The Formal Core provides the mathematical structure.

The domain layer provides domain-specific meaning.

---

## Summary

ASM Formal Core defines systems through:

Information preservation:

$$
Reality
\rightarrow
Evidence
\rightarrow
Event
\rightarrow
History
\rightarrow
State
\rightarrow
Representation
$$

State transition:

$$
Event
\rightarrow
Effect
\rightarrow
State
$$

The central model is:

$$
\boxed{
S_{t+1}
=
\delta(S_t,\alpha(e))
}
$$

The key distinctions are:

**Event:**

What happened.

**Effect:**

What changed.

**History:**

What events occurred.

**State:**

The resulting condition.

**Representation:**

How the condition is viewed.

Therefore:

$$
\boxed{
Systems\ are\ modeled\ as\ constrained\ event-driven\ state\ transitions
}
$$

The Formal Core provides the mathematical foundation for higher-level
models.
