# ASM Formal Core Overview v1.2

## Purpose

This document provides an overview of the Formal Core of the
Accounting State Model (ASM).

The Formal Core defines the general mathematical structure used to model
systems as constrained event-driven state transitions.

Domain-specific concepts, including accounting concepts, are introduced
in higher layers.

---

## What is ASM?

**Definition:**

The Accounting State Model (ASM) is a mathematical framework for
representing systems through:

$$
Event
\rightarrow
Effect
\rightarrow
State
$$

An Event represents a cause of change.

An Effect represents the change produced by the Event.

A State represents the resulting condition of the system.

---

## Fundamental Model

**Formal expression:**

$$
S_{t+1}
=
\delta(S_t,\alpha(e))
$$

where:

- $S_t$ represents the current State.
- $e$ represents an Event.
- $\alpha(e)$ represents the Effect generated by the Event.
- $\delta$ represents the State Transition Function.

**Meaning:**

ASM separates the causal occurrence, the resulting change, and the
application of the change.

| Concept | Meaning |
| --- | --- |
| Event | What happened |
| Effect | What changed |
| State | Resulting condition |
| Transition | How the change is applied |

---

## From Reality to Representation

**Definition:**

ASM does not directly model Reality.

ASM models information obtained through Observation and transformed into
purpose-dependent Representations.

The complete information structure is:

$$
Reality
\rightarrow
Evidence
\rightarrow
Event
\rightarrow
History
\rightarrow
State
\rightarrow
Representation
$$

The mathematical structure is:

$$
\mathcal{R}
\rightarrow
\mathcal{Z}
\rightarrow
\mathcal{E}
\rightarrow
\mathcal{H}
\rightarrow
\mathcal{S}
\rightarrow
\mathcal{Y}_Q
$$

where:

- $\mathcal{R}$ represents Reality Space.
- $\mathcal{Z}$ represents Evidence Space.
- $\mathcal{E}$ represents Event Space.
- $\mathcal{H}$ represents History Space.
- $\mathcal{S}$ represents State Space.
- $\mathcal{Y}_Q$ represents Task-dependent Representation Space.

---

## Event, Effect, and History

**Definition:**

ASM contains two related structures.

### State Transition Structure

The state transition mechanism is:

$$
Event
\rightarrow
Effect
\rightarrow
State
$$

An Event generates an Effect.

The Effect is applied to the current State through the Transition
Function.

---

### Information Preservation Structure

The information preservation mechanism is:

$$
Event
\rightarrow
History
\rightarrow
State
$$

Events are preserved as History.

The current State can be reconstructed from accumulated History.

Therefore:

$$
History
\neq
State
$$

History represents the path.

State represents the current condition.

---

## Core Concepts

The Formal Core defines the following mathematical objects.

---

## Reality

**Definition:**

Reality is the domain containing objects and changes that exist
independently of the ASM model.

**Symbol:**

$$
\mathcal{R}
$$

**Meaning:**

Reality is the source from which Evidence is obtained.

ASM does not directly operate on Reality.

---

## Evidence

**Definition:**

Evidence is observable information obtained from Reality.

**Symbol:**

$$
\mathcal{Z}
$$

**Formal relationship:**

$$
Obs\subseteq\mathcal{R}\times\mathcal{Z}
$$

**Meaning:**

Evidence is an observation of Reality.

Therefore:

$$
\mathcal{Z}\neq\mathcal{R}
$$

---

## Event

**Definition:**

An Event is an occurrence recognized by ASM that produces an Effect.

**Symbol:**

$$
e
$$

**Formal expression:**

$$
e\in\mathcal{E}
$$

**Meaning:**

An Event represents the causal input of a state transition.

An Event itself is not a State change.

Therefore:

$$
Event
\neq
Effect
$$

---

## Effect

**Definition:**

An Effect is a State change generated by an Event.

**Symbol:**

$$
\alpha(e)
$$

**Formal expression:**

$$
\alpha:
\mathcal{E}
\rightarrow
\Delta\mathcal{S}
$$

**Meaning:**

Effect represents what changes when an Event occurs.

The relationship is:

$$
Event
\rightarrow
Effect
$$

Effect is not the resulting State.

---

## History

**Definition:**

History is an ordered sequence of Events and their associated times.

**Symbol:**

$$
H_t
$$

**Formal expression:**

$$
H_t\in(\mathcal{E}\times T)^*
$$

or:

$$
H_t
=
((e_1,t_1),(e_2,t_2),\dots,(e_n,t_n))
$$

where:

$$
e_i\in\mathcal{E}
$$

and:

$$
t_i\in T
$$

**Meaning:**

History records Events accumulated up to time $t$.

History is the persistent source from which State can be reconstructed.

---

## State

**Definition:**

State is the condition of the modeled system at a specific time.

**Symbol:**

$$
S_t
$$

**Formal expression:**

$$
S_t\in\mathcal{S}
$$

**Meaning:**

State represents the current condition required to describe the system.

State is derived from accumulated History.

---

## State Transition

**Definition:**

State Transition is the process of applying an Effect to a State and
obtaining a new State.

**Symbol:**

$$
\delta
$$

**Formal expression:**

$$
\delta:
\mathcal{S}
\times
\Delta\mathcal{S}
\rightarrow
\mathcal{S}
$$

such that:

$$
S_{t+1}
=
\delta(S_t,\alpha(e))
$$

**Meaning:**

The Transition Function determines how an Effect changes the current
State.

---

## State Generation

**Definition:**

State Generation is the transformation from History into State.

**Symbol:**

$$
G
$$

**Formal expression:**

$$
G:
\mathcal{H}
\rightarrow
\mathcal{S}
$$

such that:

$$
S_t=G(H_t)
$$

**Meaning:**

State is generated from accumulated History.

Different Histories may generate the same State.

Therefore:

$$
History
\neq
State
$$

---

## Flow

**Definition:**

Flow is an accumulation of Effects over a period.

**Symbol:**

$$
\mathcal{F}
$$

**Formal expression:**

For a period:

$$
\tau\subseteq T
$$

Flow is:

$$
Flow(\tau)
=
\sum_{(e,t)\in H_\tau}
\alpha(e)
$$

**Meaning:**

Effect represents an instantaneous change.

Flow represents accumulated changes.

Therefore:

$$
Effect
\neq
Flow
$$

---

## Representation

**Definition:**

Representation is a transformation of ASM information into information
suitable for a specific Task.

**Symbol:**

$$
F_Q
$$

**Formal expression:**

$$
F_Q:
\mathcal{X}_Q
\rightarrow
\mathcal{Y}_Q
$$

where:

- $\mathcal{X}_Q$ represents the information required by Task $Q$.
- $\mathcal{Y}_Q$ represents the resulting Representation Space.

**Meaning:**

Different Tasks may require different views of the same underlying
system.

---

## Task

**Definition:**

Task represents the purpose that determines required information.

**Symbol:**

$$
Q
$$

**Formal expression:**

$$
Q\in\mathcal{Q}
$$

---

## Constraint

**Definition:**

A Constraint is a condition that defines valid States.

**Symbol:**

$$
\kappa
$$

**Formal expression:**

$$
\kappa:
\mathcal{S}
\rightarrow
\mathbb{R}
$$

A valid State satisfies:

$$
\kappa(S_t)=0
$$

**Meaning:**

Constraints define invariant properties that must be preserved.

---

## Formal Core Structure

**Definition:**

The Formal Core consists of:

| Document | Purpose |
| --- | --- |
| Notation | Defines mathematical symbols |
| Axioms | Defines fundamental assumptions |
| Definitions | Defines mathematical objects |
| Theorems | Derives mathematical properties |
| Corollaries | Applies derived properties |
| Examples | Demonstrates the model |

---

## Layer Extension

**Definition:**

The Formal Core defines general mathematical structures.

Domain layers specialize these structures by introducing constrained
subspaces.

For accounting:

$$
\mathcal{E}_{acc}
\subseteq
\mathcal{E}
$$

$$
\Delta\mathcal{S}_{acc}
\subseteq
\Delta\mathcal{S}
$$

$$
\mathcal{S}_{acc}
\subseteq
\mathcal{S}
$$

**Meaning:**

The Formal Core provides mathematical structure.

The domain layer provides domain-specific meaning.

---

## Summary

ASM Formal Core defines systems through:

$$
Reality
\rightarrow
Evidence
\rightarrow
Event
\rightarrow
History
\rightarrow
State
\rightarrow
Representation
$$

The state transition structure is:

$$
Event
\rightarrow
Effect
\rightarrow
State
$$

The central equation is:

$$
\boxed{
S_{t+1}
=
\delta(S_t,\alpha(e))
}
$$

The key distinctions are:

**Event:**

What happened.

**Effect:**

What changed.

**History:**

What events occurred.

**State:**

The resulting condition.

**Representation:**

How the condition is viewed.

Therefore:

$$
\boxed{
Systems\ are\ modeled\ as\ constrained\ event-driven\ state\ transitions
}
$$
